# TestMaster threat model

- Version: 1.0.0; reviewed scope: M0–M2 design, 2026-10-05.
- Authority: [SEC-001](../../specs/07-security.md), [architecture](../../specs/02-architecture.md), [approved decisions](../adr/).
- Controls below are design requirements, not claims of completed tests, penetration testing or certification. The [traceability registry](../../traceability/registry.json) starts every obligation as `planned`.

## Assets and adversaries

Protect target credentials/API keys/cookies, local capability tokens and vault keys, private source/requirements, approval and consent records, immutable revisions and execution snapshots, truthful outcomes, audit/events, evidence and backups, the operator host/internal network/cloud metadata, agent files and unrelated user bytes. Future server profiles additionally protect workspace isolation, worker/service identity and object-storage keys.

Assume a malicious page/API, untrusted repository author or imported/generated test, poisoned PRD/OpenAPI/archive/LLM response, network attacker, compromised dependency/image/provider, authenticated user attempting IDOR, and operator misconfiguration. A host administrator can read process memory and disk or change the daemon: this model does not protect against a hostile host administrator. Model providers and relays are external trust domains, not trusted policy authorities.

## Boundaries and responsible enforcement

| Boundary | Untrusted input and protected asset | Enforcement owner and rule | Expected abuse and residual risk |
|---|---|---|---|
| CLI/API/MCP → application | Arguments, tool calls, Origin, tokens and resource IDs → jobs/secrets/consents | Application services authorize operation/workspace/project/environment; server binds loopback with bearer capability token and Origin allowlist; MCP enforces roots and session scopes (SEC-004/026/027) | Forged scope, external website driving localhost, unrestricted agent authority. A local host administrator still owns the installation. |
| Importer → normalized source/store | Repo, hooks, archives, paths and references → private filesystem and provenance | Planner parses without executing hooks/scripts; evidence/importer confine no-follow opens and bound bytes/members/depth (SEC-007/017/018/047) | Zip-slip, symlink swap, bombs, external metadata references. AST rejection is not a sandbox proof. |
| Source/page/tool result → planner/model | DOM, screenshots, comments and requirements → tool authority/private source | Treat content as data with provenance; typed fixed-authority actions, deterministic validation and review (SEC-003–006) | Prompt injection and bogus assertion weakening; model quality still needs independent oracle. |
| Controller/model gateway → provider | Authorized minimal context → source privacy and cost | User-level provider allowlist/consent, redaction, byte/token ceilings, reservation-before-call, strict schema and bounded repair (SEC-006, OPS-029/030) | Exfiltration by selected provider; contractual retention cannot be enforced by local redaction. |
| Application/dispatcher → worker/supervisor | Durable jobs, claims and approval references → ownership and external effects | Admission preconditions, transaction/outbox, expiring lease and fencing on every mutation, immutable snapshot (SEC-002/031/038/039, OPS-008/010) | Duplicate/stale worker or approval reuse. A crash after target mutation can leave uncertain effect. |
| Supervisor → per-Attempt sandbox | Untrusted TS/Python/browser code → host/kernel/secrets | Fresh non-root container, hardened rootfs/caps/seccomp/quotas, pinned image, no dangerous mounts, Chromium sandbox enabled (SEC-014–016) | Kernel/runtime exploit. | Sandbox → host egress proxy → target | Sockets/CONNECT/headers/DNS/redirects → network and target policy | Network namespace has no external route; host proxy validates exact origins/all IP answers and pins address; separate controller policy; cancellation/lease loss closes gateway (SEC-008–013) | SSRF/rebinding/proxy chaining/raw socket escape. | Runner → supervisor protocol | Forged events/artifact paths/logs → verdict/state/host disk | Dedicated one-connection nonce handshake; strict NDJSON schema/sequence/identity/limits/fence, host hash recomputation and quota enforcement (SEC-019, OPS-004/008) | Forged completion, log injection or flooding. | Vault → authorized Attempt | Secret request → credential confidentiality | Declared refs, scope/version/revocation at just-in-time release over protocol; no disk/argv storage; ephemeral lifecycle cleanup (SEC-020–025) | Secret enumeration, replay after revoke. | Supervisor → evidence store/backups | Arbitrary bytes/manifests → private files and truthful history | Confinement/no-follow/type checks, bounded staging, supervisor canary scan, meta-last atomic commit, hashes/snapshot refs and private permissions (SEC-017/018/032/033/036, OPS-020/024/025) | Path escape, mixed snapshots, raw fallback, interrupted commits. | Evidence gateway/viewer → user browser | HTML/SVG/log/title/Markdown → user session | Reports escape HTML/XML with restrictive CSP; active formats attachment or isolated viewer; authorize every read/Range, recheck tombstones and restrictedRaw grant (SEC-032–037) | Stored XSS or stale signed link. | Installer → agent files | Root/path/markers/current bytes → custom agent settings | Official target paths verified before enabling; no-follow confinement, locks, preview, mode-preserving backup and atomic writes; hash/marker ownership on uninstall (SEC-017, INT-034–039) | Symlink clobber, concurrent writes or malicious duplicate markers. Agent tool permissions are not expanded by a skill file. |
| Future tunnel agent ↔ relay → loopback | Remote streams/replayed tokens → local host port | M5 disabled; before enabling require exact address/port, mutual identities, one-time token, owner/borrower binding, TTL/revocation and quotas (SEC-041–044) | Generic LAN proxy, cross-owner hijack. | Future workspace → workspace | IDs/cache/jobs/blobs/search → other tenant data | M4/M5 disabled; require identity-derived scope, composite constraints/RLS-equivalent defense, scoped cache/storage and no volume/credential reuse (SEC-027/030) | Cross-tenant IDOR and existence side channels; container isolation alone is insufficient. |

| TM-009 | Elevation of privilege | PRD/DOM/model requests shell, secrets or approval; weakens assertion | Typed bounded tools and immutable controller policy; proposals require review; no eval/shell/tool expansion (SEC-003–007/038/039) | Injection fixtures through each channel; independent oracle keeps mutant red. |
| TM-010 | Tampering / elevation | Path traversal, symlink race, archive special node or installer clobber | Filesystem no-follow/type checks, archive member verification, confined atomic managed writes (SEC-017/018, INT-034–037) | Swap symlink/hardlink/duplicate-member/bomb and concurrent install; foreign bytes survive. |

## Approved profile and residual risks

The approved M0–M2 deployment is single-user Linux x64 with rootful hardened Docker, not an untrusted multi-tenant hosting service. See [ADR-003](../adr/003-rootful-docker.md). Docker group membership is effectively host-root authority. Daemon/runtime/kernel bugs may break isolation; use segregated hosts/VMs for adversaries requiring a stronger boundary. Rootless reduces daemon privilege but still shares the kernel and has not been validated here.

Unsafe process execution requires `execution.executor: "process"`, `--unsafe-local` and user-level `security.allowUnsafeProcessExecution: true`; it possesses the user's privileges and can bypass local network/filesystem restrictions. It is not a substitute for the hardened Docker profile. Missing Docker, proxy, policy or credentials blocks before effects; no automatic fallback.

Redaction is best effort for unknown PII, canvas/media and transformed/encoded secrets. Raw traces/videos are disabled by default; no unsupported trace transformation is labeled redacted. Minimize collection and restrict authorized raw access. Encryption at rest does not hide secrets from an authorized host administrator. Provider data retention requires verified provider terms, not an invented guarantee.

Cancel/retry cannot roll back a payment, deletion or uncertain external mutation. Only target-supported idempotency and explicit reconciliation reduce this risk; resource uncertainty and cleanup failure remain visible and non-green when required. A malicious approved target can consume credentials legitimately sent to it. Deterministic schemas, signatures and hashes do not prove business correctness: independent oracles and healthy/defective controls do.

M3–M6 capabilities, including multi-user tenancy, remote tunnels, SSO and plugins, must return `CAPABILITY_UNAVAILABLE` with milestone until enabled by their gates. Documentation of their boundary is not implementation.

## Change and review policy

The Security owner must update this versioned model before enabling a new executor, transport, integration, secret-access path, raw evidence format or agent target. Review assets, all new edges, enforcement outside untrusted code, positive/negative controls and residual risks; update the owning SEC/scenario/oracle/evidence links. High/critical release-scope risks and evidence falsification block release (VAL-046); no average benchmark score compensates for them. No status becomes `verified` from this document alone.
